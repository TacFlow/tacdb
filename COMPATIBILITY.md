# Compatibility matrix

Policy (§25.1 and §28 of the specification): tacdb aims at functional and semantic parity with the reference engine (R0) in the inventoried capabilities. Every difference has an ID, a reason and a test in this matrix; no divergence disappears without a record.

## 1. Areas

| Area | Policy (§28) | Status |
|---|---|---|
| Property/graph model | Parity, including absence/Null, lists/maps and edge IDs. | Values and codec ready (M1a); nodes, edges, labels, properties, adjacency and degrees ready (M3b); property indexes with uniqueness, truncated and hashed keys ready (M3c); online BuildIndex ready (M3d). |
| Cypher dialect of the pinned revision | Parity on the inventoried features. | Parser of `tacdb-cypher/1` ready (M4a): every clause and the precedence table of the reference, with the divergences D-009 and D-010. Semantic analysis, expressions, the 26 functions and the aggregates ready (M4b), with the divergences D-011 to D-014; execution of read queries with the syntactic plan ready (M4c), with the divergences D-015 and D-016; writes, the planner by cost and the plan cache pending (M4d to M4f). |
| FTS/BM25/fuzzy | Functional parity; deterministic scores across platforms. | Pending (M5). |
| HNSW | Same capabilities and metrics; topology is not a binary identity. | Pending (M8). |
| Transactions | One mutating writer; parallel readers; adaptive group commit. | Ready (M2): FIFO writer queue, snapshots, O(1) savepoints, GroupSync, Sync and Async; public API of handles and transactions (M3b). |
| Physical maintenance | Passive checkpoint, segmented WAL, bitmap allocator, scrub, compact. | Page format and superblock (M1c), allocator (M1e), segmented WAL, passive checkpoint and scrub (M2) ready; compact pending (M9). |
| Cluster/multiprocess | Mandatory in 1.0. | Pending (M10 to M12). |
| Streams | Sequences, offsets, trim and atomicity preserved. | Pending (M6). |
| Security | The §20 model, with no counterpart in R0. | File permissions, paths and locks ready (M1b, see SECURITY.md); the rest pending (M10). |
| R0 main file/WAL | Physically incompatible; migration through LTX1. | By decision (ADR-07). |
| Original Go API | Conformance adapter; new main API. | Pending. |
| C ABI / Python / Java | Outside the initial distribution. | By decision. |
| TypeScript | New SDK over a Go bridge. | Pending (M10, M13). |
| Neo4j-inspired improvements | tacdb's own Go implementation of the §33 contracts, clean room; no binary compatibility, Bolt or Enterprise extension. | Slotted rows, ExpandInto by the adjacency prefix of the peer, TopK and the ordered aggregate ready (M4c); the rest pending (M4e onwards). |
| Memory/serialize | Shared VFS; Serialize produces a consistent G2 snapshot without quiescence. | MemoryVFS ready (M1b); Serialize pending (M9). |
| Embedding helpers/services | Excluded from the runtime; external vectors are optionally accepted. | By decision (ADR-03). |
| TAC | Language 0.6 and IR 1.3 for the database; new constructs are not skill aliases. | Pending (M7). |
| LAYA/SLM constructs and implicit legacy memory | Absent from the profile; an error or an explicit source migration. | Pending (M7). |
| Performance | No promise of automatic improvement; compare and record; write amplification has a gate. | Concurrency and isolated-commit benchmarks and the REC-11 gate run in CI (M2); the rest pending. |
| G2 limits | IDs and sequences up to MaxInt64; fixed limits require a new `format_revision`. | Value limits (M1a) and page limits (M1c) ready. |

## 2. tacdb's own decisions

| ID | Decision | Reason | Test |
|---|---|---|---|
| D-001 | Total order of values: Bool < number < String < Bytes < Vector < List < Map < Null. Int and Float compare by exact numeric value, without converting int64 to float64; NaN comes after every number and ties with any NaN; `-0` ties with `+0`. `Compare == 0` does not imply equal bits (`Int(1)` and `Float(1)` tie). | §5.3 fixes the families and asks for tacdb's own cases where R0 does not fix the behavior. | `value/compare_test.go` |
| D-002 | Canonical codec: the decoder rejects map keys out of order or repeated, and non-minimal uvarints, as `CORRUPT`. | Every value has a single form (§5.3 and §7.1 of specification 1.3); goldens and signatures depend on it. | `internal/codec/value_test.go`, `internal/codec/uvarint_test.go`, `FuzzValue` |
| D-003 | The REC-11 gate (an open after a crash over a database of 100 GiB) runs on Linux and macOS only. | It needs a sparse main file; on Windows that takes an explicit attribute, and the property it measures, a recovery that never reads the main file beyond its superblock, does not depend on the platform. | `internal/engine/gate_test.go` (`TestREC11`) |
| D-004 | The graph methods of `Tx` take no context, as §6 declares them; they are bounded by `MaxWriteTxDuration` and `MaxReadTxAge`. `Commit` of a read transaction closes it and returns its snapshot with a zero token. Inside `View` and `Update`, `Commit` and `Rollback` fail with `INVALID_ARGUMENT`: the function owns the work, not the transaction; a call `fn` left running ends before the transaction does. `Close` with transactions open returns `BUSY`; a transaction that begins while `Close` checks fails with `SHUTTING_DOWN`. | §6 leaves these cases open. | `db_test.go` (`TestUpdate`, `TestTransactions`) |
| D-005 | `EdgeCursor` reads the adjacency in batches of 64 entries, each one operation of its transaction that resumes after the last key it gave, and checks its transaction before each edge: after `Commit`, `Rollback` or an expired snapshot it fails at once (`TX_CLOSED`, `SNAPSHOT_EXPIRED`). Inside a write transaction it yields the edges that existed when it was opened and still exist when it reaches them, so writing during the walk never feeds it. Edges come grouped by direction (outgoing, then incoming) and type, in peer and edge order. | Without a live cursor in the engine, a resumable cursor keeps revocation cooperative (§10.1); the rule for writes does not depend on the batch size. | `internal/graph/graph_test.go` (`TestCursorBatches`, `TestCursorExpires`), `cursor_test.go` |
| D-006 | The canonical dump writes one line per node, then per edge, in ID order: labels in insertion order, properties by name, values typed and exact (`1` is Int, `float(1)` Float; `-0`, infinities and NaN bits kept). | The dump of §25.1 compares content and keeps the bits of properties. | `internal/graph/graph_test.go` (`TestDumpValues`) |
| D-007 | A seek on a property index applies expression semantics to the full value: equality finds Int 1 and Float 1.0 together, and never matches Null or NaN; a range only matches values of the family of its bounds (numbers are one family); `STARTS WITH` only matches strings. Hits come by value, then by entity ID. Indexes hold an entry for a stored Null, never for an absent property. | §12.2 fixes the keys and uniqueness, §15.2 the semantics of comparisons; ties need a stable order. | `internal/index/index_test.go` (`TestSeekAgainstScan`) |
| D-008 | `BuildIndex` waits for the end of the build or of its context, and the build goes on after the context ends; a close of the handle returns `CLOSED` and a drop `INDEX_NOT_FOUND`. `IndexBuildStatus.Conflicts` adds the first pairs of entities with equal values to the status of §12.2. A batch takes at most half of `MaxTxBytes`. `DropIndex` purges entries after its commit, in batches, for every index; `CreateIndex` and `BuildIndex` of an identical declaration return at once whatever its state, so a FAILED index must be dropped before it is built again. | §12.2 leaves the waiting, the shape of the conflicting keys and the purge open. | `build_test.go` |
| D-009 | Lexical divergences from the reference: one statement per query, with an optional final `;` (the reference reads `;` as whitespace and merges statements); names between backticks, with a doubled backtick for a backtick, so that `QuoteIdentifier` output parses; keywords allowed as labels, types, property keys and map keys; an invalid `\u` escape, a float literal out of range, a number glued to letters, a bare `$`, a float literal that rounds to zero and a NUL inside a quoted name are `QUERY_LEX` errors (the reference keeps text, gives +Inf or 0.0, or splits the token); `-9223372036854775808` is an Int literal. Errors carry their stage and line and column, the column in code points. | SPEC §15.1, §20.7; nothing accepted in part. | `internal/query/parser/parser_test.go` (`TestLiterals`, `TestErrors`), `query/query_test.go` |
| D-010 | Clause structure follows Cypher instead of the reference's free order: reading clauses, then updates, in parts separated by WITH; WHERE only after MATCH, OPTIONAL MATCH, WITH or CALL; ORDER BY, SKIP and LIMIT only inside RETURN or WITH, in that order; RETURN last; a query ends in RETURN or an update, or is a single CALL; `RETURN 1` alone is valid and an empty query is an error. Constructions outside the dialect (UNION, CASE, list indexing and comprehensions, `RETURN *`, `=~`, path variables, pattern predicates, map projection, label predicates in expressions, subqueries, schema commands) are `QUERY_UNSUPPORTED`, naming the construction. Relationship type alternation `:A\|B` is accepted in patterns; a variable-length relationship takes neither a variable nor properties. Expressions keep the reference's precedence table, including prefix NOT as any operand (`a = NOT b`) and operators after `IS NULL` (`a IS NULL + b`). | SPEC §15.1. | `internal/query/parser/parser_test.go` (`TestClauses`, `TestUnsupported`) |
| D-011 | Expressions: `=` and `<>` compare Int and Float by exact value, lists and maps item by item with the same `=` (`[1] = [1.0]`, `[null] = [null]`), entities by kind and ID; NaN equals nothing; `IN` uses that `=`, so `[1] IN [[1]]` is true. `<`, `<=`, `>`, `>=` order Bools, numbers, Strings and Bytes within their family, any other pair is Null, and NaN makes them false (the reference computes `>` as `NOT <=`). Integer `+ - * / %`, negation and `abs` refuse overflow with `INVALID_ARGUMENT`; `/` and `%` by zero are errors for floats too; `%` on floats is the floored remainder with the sign of the divisor, like the Int `%`. `+` concatenates two Strings, two Lists, or a List and an element; `-null` and every other operator on Null are Null; `m.k` reads a map key; a variable or parameter bound to Null reads as Null; a missing parameter is `PARAM_MISSING` before execution. Every NaN computed by an operator is the NaN of `math.NaN`, and `^` uses a portable `pow`, so results are bit-for-bit the same on amd64 and arm64. The runtime order extends D-001 with entities (nodes before edges, by ID) and paths after Maps, then Null. | SPEC §5.3, §15.2, §31.3, DET-01; the reference leaves overflow undefined and its NaN and list cases are defects. | `internal/query/eval/testdata/expressions.json`, `internal/query/eval/det_test.go`, `internal/query/qv/qv_test.go` |
| D-012 | Functions: names ignore ASCII case, unknown names and wrong arities are `QUERY_SEMANTIC` before execution, and DISTINCT on a scalar function is refused. Every scalar function except `coalesce` gives Null for a Null argument (the reference gives a type error for `id`, `abs`, `size`, `range`, `substring` and others, and `'null'` for `toString(null)`). `size` counts code points and `substring` takes code points, so no String is split inside a character (the reference counts bytes). `split(s, '')` splits into code points; `toInteger` of NaN, an infinity or a float beyond Int is `INVALID_ARGUMENT`; `range` refuses a step of 0 and more elements than `MaxValueElements` before it allocates, and never overflows; `properties` gives a Map sorted by key. The rest follows the reference fixtures: ASCII-only `toLower`/`toUpper`, `trim` of four characters, `'_'` separators in `toInteger` and `toFloat`, plain-decimal `toString` of floats. | SPEC §15.1, §15.2 (`functions.json` as the contract); nothing accepted in part. | `internal/query/eval/testdata/functions.json` |
| D-013 | Aggregates: `count(*)` (and its synonym `count()`) counts rows, every other aggregate skips Null; DISTINCT and grouping use the codec of equality, so `1` and `1.0` are one value and `-0` and `+0` one key. `sum` of Ints is an Int that refuses overflow of its final value, any Float makes it a Float, and no value gives Int 0; `avg` of no value is Null; both refuse non-numbers with `TYPE_MISMATCH` and add exactly (128-bit Ints, floats scaled by 2^1074) with one final rounding, so the result does not depend on the order of the rows. `min` and `max` use the total order of D-011 and break ties between equal but different values (Int 1 and Float 1.0) by kind and bits, not by row order. An exact sum has no sign of zero: a Float sum that is zero is +0.0, even of `-0.0` alone. `collect` skips Null and keeps entities. | SPEC §15.2, DET-01; the reference sums in float64, counts Null in `avg`, keeps Null in `collect` and depends on row order for ties. | `internal/query/eval/testdata/functions.json` (`aggregates`), `internal/query/eval/det_test.go` |
| D-014 | Semantic analysis, before any effect: variables resolve by scope, and a WITH replaces the scope by its items, each non-variable item needing an alias; duplicate column names and duplicate keys in map literals are refused; a column without alias is named by its text with spaces and comments made one space. An aggregating projection groups by its other items; outside its aggregates it reads the rows only through those grouping keys. ORDER BY sees the items, plus the earlier variables when the projection neither aggregates nor uses DISTINCT, and an aggregating projection may order by aggregates. SKIP and LIMIT take an Int literal >= 0 or a parameter, checked before execution. CREATE needs one type and a direction per relationship and refuses labels or properties on a bound node; MERGE refuses a Null property and a Null parameter there; SET and REMOVE need nodes or relationships, labels need nodes. An operator whose operand types are both known and that cannot succeed (`'a' - 1`, `n < 1` with `n` a node, `true + 1`) is `QUERY_SEMANTIC`; `'a' + 'b'` and `WHERE 1` are valid. Bindings in scope above the limit and parameters above `MaxParams` are `LIMIT_EXCEEDED`. | SPEC §15.2, §15.3, §15.4, §31.3. | `internal/query/sema/sema_test.go` |
| D-015 | Read execution: the relationships of all the patterns of one MATCH or OPTIONAL MATCH are distinct within a row, never across clauses; an undirected self-loop matches once; a variable repeated in a pattern or bound by an earlier clause is the same entity. A variable-length relationship takes type alternation and enumerates, depth first, every path of distinct edges, one row per path; `*0` binds its end to its start; without a maximum it stops at `MaxHops`, and a path that could go on past it is `RESOURCE_LIMIT`, like an explicit maximum or minimum above `MaxHops`; `MaxExpansions` bounds the edges the variable-length relationships of a query read. An expansion from Null yields nothing, and a property map matches by the `=` of expressions, so `{k: null}` matches an absent property. OPTIONAL MATCH is a left outer apply whose WHERE stays inside it. UNWIND of Null gives no row and of any other non-List one row. The WHERE of a WITH filters after its ORDER BY, SKIP and LIMIT. ORDER BY is stable, by the total order of D-011, Null last ascending and first descending; TopK, which keeps SKIP plus LIMIT rows, and the ordered aggregate give what a full sort and the hash aggregate give. Bindings count the variables in scope, not the items of RETURN, which are columns. | SPEC §15.2, §15.3, §15.5, §33.3 to §33.5; the reference has no OPTIONAL MATCH and no edge isomorphism, matches a self-loop twice, keeps the first discovery of each node of a variable-length path, caps `*` at 100 in silence and gives one row for UNWIND of Null. | `testdata/corpus/read.json`, `oracle_test.go`, `query_test.go` (`TestOptionalMatch`, `TestTopKAndOrderedAggregate`, `TestQueryErrors`) |
| D-016 | Reads through the API: `DB.Query` and `Tx.Query` run read queries; a query that writes is `QUERY_WRITE_REQUIRES_EXEC` until `Exec` (M4d); `EXPLAIN`, `PROFILE` and `CALL` wait for M4f; `<=>`, `@@` and `USING VECTOR` are `QUERY_UNSUPPORTED` when planned, whatever the data, until their indexes (M5, M8). Nodes, edges and paths come materialized, inside lists and maps too; `Values` is valid until the next `Next` and `CloneValues` copies. A `Rows` belongs to its transaction: while it is open, `Commit` and writes in the transaction are `BUSY`; `Rollback` and the end of `View` close it with `TX_CLOSED`; an expired snapshot gives `SNAPSHOT_EXPIRED`; the `Rows` of `DB.Query` owns its read transaction. `QueryMemoryBytes` is charged to the execution category of the governor before sort, TopK, aggregation and DISTINCT keep values, and for the current row once it is materialized, at no less than a value takes in memory; `QueryWorkUnits` counts rows produced by operators, entities scanned and edges read, and the context and the snapshot are checked every 256 of them; errors of the execution carry the stage `execute`, and those of a variable-length relationship its location. An ID seek finds the node whose ID equals the value by the `=` of expressions, so `id(n) = 1.0` finds node 1. `QueryStats` adds the entities examined and the plan mode. The convenience calls of §31.1 scan in ID order and find by the equality of an index seek (D-007). | SPEC §15.4, §31.1; the reference has no cursor contract and returns entities as IDs. | `query_test.go` (`TestRowsLifecycle`, `TestQueryValues`, `TestQueryBudget`), `convenience_test.go`, `gov01_test.go` |
